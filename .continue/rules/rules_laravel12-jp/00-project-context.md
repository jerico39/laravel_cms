# プロジェクトコンテキスト

## 基本方針

このプロジェクトは、VS Codeで開いているフォルダ全体を1つのLaravelプロジェクトとして扱う。

ユーザーが「プロジェクト」「既存コード」「システム全体」と表現した場合は、現在のWorkspace全体を対象とする。

実装前に、必要に応じて以下を確認する。

- composer.json
- package.json
- .env.example
- routes/
- app/
- config/
- database/
- resources/
- tests/
- docker/
- docker-compose.yml
- README.md

## 既存コード優先

新規実装を行う場合、最初に既存コードの構造、命名規則、設計パターンを確認する。

既存の実装パターンが存在する場合は、独自の新しい方式を導入せず、既存パターンに合わせる。

同じ目的の処理が既に存在する場合は、重複実装を避ける。

## 変更範囲

要求された機能に必要な最小限のファイルだけを変更する。

関係のないファイルを変更しない。

既存の動作を破壊する可能性がある場合は、変更前にそのリスクを説明する。

## 回答言語

ユーザーへの説明は日本語で行う。

コード内の変数名、クラス名、メソッド名は、プロジェクト既存の命名規則に従う。

コメントは、必要な場合のみ日本語で記述する。
